# KeyLayers Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An end-user website for KeyLayers at `https://johannes.plunien.com/KeyLayers/` (home with the
author's story, a screenshot-per-step setup guide, usage docs, a contributors section), deployed from
`docs/` by GitHub Actions, with a slimmed README.

**Architecture:** VitePress builds `docs/` in place (`srcExclude: ['superpowers/**']`). A global `<Shot>`
component shows light/dark screenshot pairs from `docs/public/screenshots/`. App screenshots come from the
snapshot tests (`site:images`); System Settings screenshots from a guided capture in a throwaway tart VM
cloned from a prepared base (`site:screenshots`). A Pages workflow builds on PRs and deploys on `main`.

**Tech Stack:** VitePress 1.6.x, Node 26 and aube 2.10.1 (via mise), bash mise tasks, tart 2.29, GitHub
Actions Pages, swift-snapshot-testing (existing).

**Spec:** `docs/superpowers/specs/2026-11-21-website-design.md`

## Global Constraints

- Site URL `https://johannes.plunien.com/KeyLayers/`; VitePress `base: '/KeyLayers/'`; no CNAME file.
- `mise.toml` pins `node = "26.13.1"` and `aube = "2.10.1"`; Node packages only via aube; `aube-lock.yaml` committed; CI uses `aube install --frozen-lockfile`.
- Every entry point is a mise task: one executable bash file under `mise/tasks/site/` with a `#MISE description=` line, `set -euo pipefail`, `cd "$MISE_PROJECT_ROOT"` (the repo's pattern, see `mise/tasks/readme/images`).
- Download link: `https://github.com/plu/KeyLayers/releases/latest/download/KeyLayers.zip`.
- Input Monitoring path: `/Applications/KeyLayers.app/Contents/Library/HelperTools/KeyLayersInputDaemon`.
- Screenshot files: `docs/public/screenshots/<group>/<name>.<light|dark>.png`, groups `app` and `system-settings`; PNGs are in Git LFS (existing `.gitattributes`).
- System Settings shot names: `gatekeeper-open`, `login-items-approve`, `accessibility`, `input-monitoring-add`, `input-monitoring-goto`, `input-monitoring-enabled`.
- Screenshot VM: base `keylayers-screenshots-base` cloned from `ghcr.io/cirruslabs/macos-tahoe-xcode:27`; per-run clone `keylayers-screenshots`; `claude-dev` is never used.
- `docs/superpowers/**` and `AGENTS.md` are never published.
- Conventional commits (AGENTS.md); `mise run lint` and `mise run test:unit` pass before pushing.

## Review Focus

- Raw HTML `<img>` under a non-root base: paths without `withBase` 404 on the live site. Pinned by Task 1's `site:check` (built HTML references `/KeyLayers/screenshots/`, never `"/screenshots/`).
- A screenshot referenced by `<Shot>` but missing, or one variant missing: silent broken image. Pinned by `site:check` (every `<Shot name>` has both `.light.png` and `.dark.png`).
- Git LFS pointer files deployed instead of PNGs (checkout without LFS): every screenshot broken. Pinned by `site:check` (every PNG in `dist` starts with the PNG signature) and run in CI before upload.
- Internal plans/specs published: pinned by `site:check` (no `superpowers` path in `dist`).
- `site:screenshots` interrupted (Ctrl-C) or failing mid-run leaves the clone `keylayers-screenshots` running and on disk: pinned by Task 3 Step 4 (interrupt test, `tart list` shows no clone).
